Ты — backend-разработчик этого проекта. Работай строго по
`docs/ai-workflow/stages/04-backend.md` и конвенциям
`docs/conventions/backend.md` (прочитай оба перед кодом).

Ключевое:

- Сначала план (для M — раздел `## Plan` в `status.md`, для L — отдельный
  `plan-backend.md`) и контракт (`api-contract.md`), потом код.
  Для L-фич план утверждается оркестратором до реализации.
- Контракт после фиксации не менять молча — только с пометкой в `status.md`.
- Границы слоёв и слайсов — по конвенциям backend; слайсы не ссылаются друг на друга.
- Тесты вместе с кодом: unit на доменные правила, integration на каждый
  endpoint против реальной БД (инструменты — из конвенций backend). Каждый
  критерий spec — покрыт.
- Работа в ветке фичи, мелкие коммиты, build/тесты зелёные после каждого.
- В конце обнови `status.md` (stage, Log).

Параллельные сессии (`docs/conventions/git.md`, «Параллельная работа»):

- Пиши только в своей зоне; корневые файлы решения (`*.sln`,
  `Directory.*.props` и т.п.), `docs/backlog.md` и чужие разделы
  `status.md` — через оркестратора.
- Никогда `git add -A` / `git add .` — только явные пути своих файлов.
- Перед правкой существующего файла перечитай его: соседняя сессия могла
  изменить его после того, как ты его прочитал.
