# Этапы 6–7 — Frontend: разработка + QA

**Роли:** frontend-developer, qa-engineer (QA — отдельная сессия) · **Модель:** standard
**Вход:** `spec.md`, `design.md`, `api-contract.md`, `docs/conventions/frontend.md`
**Выход:** код + тесты в ветке фичи, `docs/features/<id>/qa.md` (раздел Frontend)

Этап может стартовать параллельно с QA backend: разработка ведётся против
`api-contract.md`, до готовности backend — на моках API (инструмент — по
конвенциям frontend).

## 6a. План

1. Прочитать конвенции frontend и код соседних slice'ов (features/).
2. Написать план: для M — раздел `## Plan` (5–10 строк) в `status.md` фичи;
   для L — отдельный `plan-frontend.md`. Содержание: новые фичи-слайсы,
   страницы/роуты, компоненты, состояние (server state / client state),
   какие компоненты дизайн-системы используются.

## 6b. Разработка

- Строго по `docs/conventions/frontend.md`.
- Реализовать **все состояния из design.md**: loading, empty, error, права.
  Экран без empty/error-состояний — незавершённая работа.
- API-слой генерируется/пишется строго по `api-contract.md`; расхождение
  контракта с реальным API — блокер, эскалация оркестратору, а не «подгоню
  на фронте».
- Тесты вместе с кодом: unit на логику (хуки, утилиты), компонентные на
  ключевые сценарии, моки для API — инструменты из конвенций frontend.
- Тексты интерфейса — из design.md, не придумывать свои.

## 7. QA frontend (отдельная сессия, чистый контекст)

1. Раздел **Frontend** в `qa.md` фичи по шаблону test-plan: матрица
   критерий/экран → проверка.
2. Прогнать тесты, дописать недостающие компонентные тесты.
3. E2E ключевого сценария фичи (e2e-инструмент проекта) против реального backend —
   минимум happy path + один отказной сценарий.
4. Сверка с design.md: все экраны, все состояния, тексты, поведение прав.
5. Дефекты → раздел Frontend `qa.md` → возврат frontend-developer'у,
   цикл до пустого списка блокеров.

Правила экономии прогонов — общие с backend-QA, см.
[04-backend.md](04-backend.md), раздел «Экономия прогонов». E2E — единственное
исключение из правила «зелёное не перепроверяется»: e2e-сценарий прогоняется
повторно, если первый прогон был на моках, а не против реального backend.

## Definition of Done

- [ ] Все экраны и состояния из design.md реализованы
- [ ] Компонентные тесты + e2e happy path зелёные
- [ ] Нет расхождений с api-contract.md
- [ ] `qa.md`, раздел Frontend: блокеров нет
- [ ] `status.md`: `stage: 06-review-complete`
